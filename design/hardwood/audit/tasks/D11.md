# D11 · Replace "№" with "No." (the mono font has no № glyph)

## 1. Problem
"№" renders in a fallback font (visibly off-weight) on the ticket band ("PAPER TICKET · № 0190"), the stub's vertical
number ("TICKET № 0190") and the drawer kicker ("BACK OF TICKET · № 0190"). Ruling 7 allowed the fallback; the audit
asks for "No." in the mono font instead. Screenshot: `design/hardwood/audit/shots/D7-D11-names-glyph-1440.png`.

## 2. Repro
`/?sample=1&scene=live` at 1440 (and 400): tickets; open a drawer. Grep: `grep -rn "№" public/static/js public/*.html`.

## 3. Root cause
- `public/static/js/tonight/tickets.js` line ~97 (stub `.no`: `'Ticket № ' + no`) and ~144 (band: `'Paper ticket · № ' + no`).
- `public/static/js/tonight/drawer.js` line ~73 (kicker: `'Back of ticket · № ' + …`).

## 4. Files owned
- `public/static/js/tonight/tickets.js` (only those two strings)
- `public/static/js/tonight/drawer.js` (only that string)

## 5. Complete solution looks like
- "Ticket No. 0190", "Paper ticket · No. 0190", "Back of ticket · No. 0190" (CSS uppercases them → "NO. 0190").
- `grep -rn "№" public/static/js public/*.html` finds nothing.
- Nothing else changes.

## 6. Out of scope
Stub layout (D5), dashes (D4).

## 7. Acceptance tests (`tests/e2e/audit/D11.mjs`)
At 400 and 1440: no text node on Tonight (tickets + open drawer) contains '№'; the band and drawer kicker contain
'No. ' followed by 4 digits. The grep returns nothing (run it with `child_process.execSync` in the test, or report it).
`page.errors` empty.

## 8. Evidence to return
Diff, test output, element screenshot `D11-1440` of the first ticket and `D11-drawer-1440` of the drawer header (+ before).
