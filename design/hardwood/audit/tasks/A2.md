# A2 · No empty model facts when `production_model` is null

## 1. Problem
When `/api/model` returns `production_model: null` (and `trained_at: null`), the Model hero kicker reads just
"THE MODEL", and Tonight's model-facts card shows "Live model —" and "Retrained —".
Screenshot: `design/hardwood/audit/shots/A1-model-page-without-featured-game.png` (hero at the top).

## 2. Repro
`/model?sample=1` and `/?sample=1&scene=live` (scroll to `[data-testid=mfacts]`) at 400/768/1440 with the model patched:
`route: [['**/sample/model.json', async r => { const j = await (await r.fetch()).json(); j.production_model = null; j.trained_at = null; await r.fulfill({ json: j }); }]]`

## 3. Root cause
- `public/static/js/model/claim.js` `initClaim()` lines ~66–71: kicker = `['The model', production_model?, 'retrained …'?]`
  joined with ' · '; both null → "The model".
- `public/static/js/tonight/season.js` `mountModelCard()` lines ~294–310: always writes "Live model" and "Retrained"
  rows, with '—' when null.

## 4. Files owned
- `public/static/js/model/claim.js` (only the kicker lines in `initClaim`)
- `public/static/js/tonight/season.js` (only `mountModelCard`)

## 5. Complete solution looks like
- Model hero `[data-kicker]`:
  - production_model present → unchanged (A3 later changes how the name reads; leave the raw name for now).
  - production_model null → exactly `The model · Production model unavailable`, plus ` · retrained <date>` if trained_at
    is valid. (CSS uppercases it; write sentence case.)
- Tonight `[data-testid=mfacts]`: build the rows, then drop the "Live model" row when production_model is null and the
  "Retrained" row when trained_at is null/invalid. The other four rows are unchanged. The `sep` class (top rule above
  "This season") is applied only when at least one row precedes "This season".
- Normal sample data: nothing changes. All widths and reduced motion: same.

## 6. Out of scope
Friendly model names (A3), any other code in claim.js / season.js.

## 7. Acceptance tests (`tests/e2e/audit/A2.mjs`)
For w in 400, 768, 1440, patched model:
- Model page: `[data-kicker]` textContent === `The model · Production model unavailable`.
- Tonight: no `[data-testid=mfacts] dd` with trimmed text '' or '—'; no dt 'Live model' or 'Retrained';
  the first dt has no `sep` class.
- Audit "Accept when" — *No empty dd/fact cells when production_model is null*: on both pages, every visible `dd`
  outside `[data-testid=tape]` and `[data-testid=season-board]` has non-empty text other than '—'.
- Unpatched: kicker starts with 'The model · ' and contains 'retrained'; mfacts has 6 dt.
- `page.errors` empty.
