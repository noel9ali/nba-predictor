# C8 · Weights chapter: visible grid lines; values right after their bars

## 1. Problem
Model Chapter 4 ("What it leans on"): the 10% grid lines behind the bars are nearly invisible, and at 1440 the
percentage values sit far to the right of short bars (in a fixed right column), so it's hard to tell which value
belongs to which bar.

## 2. Repro
`/model?sample=1` at 400, 768, 1440: `scrollTo(p, '#ch4 .wts', 1500)` (bars grow in over ~0.9s).

## 3. Root cause
- `public/static/css/model.css` ~87–109: `.wts .w{grid-template-columns:minmax(0,15em) minmax(0,1fr) 4em}` puts `.val`
  in its own 4em column at the far right; `.wts .tr{background:linear-gradient(90deg,var(--edge) 1px,transparent 1px) 0 0/10% 100%}`
  draws the grid in `--edge`, which is very close to the card colour.
- `public/static/js/model/weights.js` `row()` ~25–36 appends `nm`, `tr` (with the bar `i`), `val` as siblings.

## 4. Files owned
- `public/static/js/model/weights.js` (only `row()`)
- `public/static/css/model.css` (only `.wts …` rules)

## 5. Complete solution looks like
- Grid lines: 1px lines every 10% in `color-mix(in srgb, var(--ink) 18%, transparent)` (≈ alpha .18 of the ink colour).
  Keep the 10% spacing and the caption "Grid lines every 10%".
- Values: move `.val` inside `.tr`, absolutely positioned at the bar's end + 8px: `left: calc(<share>% + 8px)` set via
  `val.style.setProperty('left', …)`; vertically centred in the track. If `share > 0.82` (the label would leave the
  track on the right), place it inside the bar instead: `right: calc(100% − <share>% + 8px)` with `left:auto`, in the
  bar's text colour so it stays readable. Grid columns become `minmax(0,15em) minmax(0,1fr)` (desktop) and the phone
  layout (`@media` at ~95–98) keeps the track on its own row with the value at the bar end.
- The value must not overlap the bar's right border (3px `--paint`) — 8px gap from the bar's end.
- `aria`: the list's `aria-label` unchanged; `.val` still contains the text (e.g. "79.3%"), now inside `.tr` which is
  `aria-hidden="true"` → so ALSO append a visually-hidden copy of the value to `.nm` for screen readers
  (`<span class="sr">, 79.3%</span>`; `.sr` class exists in the CSS).
- The bar grow animation (`scaleX`) must not scale the value: the value is a sibling of `i` inside `.tr`, not a child of `i`.
  Values fade in after the bars (`opacity` transition .3s, delay .9s) — under reduced motion they're simply visible.
- "other" dashed row behaves the same.

## 6. Out of scope

## 7. Acceptance tests (`tests/e2e/audit/C8.mjs`)
For w in 400, 768, 1440 (after the reveal):
- For each `li.w`: `gap = valRect.left − barRect.right` is between 6 and 10px, or (inside case) the value rect is inside
  the bar rect. The value rect is inside the track rect horizontally... or for the outside case its left ≥ bar right.
- No value rect intersects another row's rect.
- Grid colour: `getComputedStyle(tr).backgroundImage` contains `color-mix` or an rgba with alpha between .15 and .25.
- Each `li.w .nm .sr` text ends with '%'.
- Reduced motion run at 400: values visible (opacity 1).
- `page.errors` empty.
