# A1 · Model page: fallback when the featured game can't load (chapter numbers stay fixed)

## 1. Problem
When `/api/game/<id>` fails (404 when `NBA_SCHEMA_V2` was off, or any network error), Chapter 3 ("How it thinks", 7
steps) and the "One game, one row" card in Chapter 2 silently disappear, and the later chapters renumber (4→3, 5→4,
6→5). No message is shown. Screenshot: `design/hardwood/audit/shots/A1-model-page-without-featured-game.png`.
(The env flag is already on in production since Oct 7; this task is only the frontend fallback.)

## 2. Repro
- `/model?sample=1` at 400, 768, 1440 with the game-detail request failing. Playwright:
  `open('/model?sample=1', w, { route: [['**/sample/game-*.json', r => r.fulfill({ status: 404, contentType: 'application/json', body: '{}' })]] })`
  (in sample mode `api.gameDetail` reads `/sample/game-<id>.json`; in production `/api/game/<id>`).
- Also with the featured pick failing: route `**/sample/featured-pick.json` to the same 404.
- Scroll to `#ch3`, and to the end of `#ch2` (`[data-rowcard-mount]`).

## 3. Root cause
`public/static/js/model.js`:
- lines 103–104: `detailP` resolves `null` when `/api/featured-pick` or `/api/game` fails.
- lines 117–125: `show(ch(3), ok)` hides `#ch3` when `d` is null; the row card is skipped.
- lines 25–34: `numberChapters()` numbers only visible `section.chapter`s, so hiding ch3 renumbers ch4–ch6.

## 4. Files owned
- `public/static/js/model.js`

## 5. Complete solution looks like
- Chapter numbers are fixed by DOM position: the n-th `section.chapter` is always "Chapter n" (`#ch1` … `#ch6`),
  whether or not other chapters are hidden. Keep `numberChapters()` exported; hidden chapters still consume their
  number. Chapters 1, 2, 4, 5, 6 may still hide when their own data is missing (unchanged).
- When the walkthrough can't render (`d` null, or `initWalkthrough` returns false or throws), `#ch3` stays
  **visible**: its `.ch` head stays ("Chapter 3", h2 "How it thinks, one pick at a time"), `[data-lede]` text is set
  to `''`, and `[data-body]` holds exactly one card, built with createElement + textContent:
  `div.card.walk-fallback[role=status] > p` with text `Walkthrough unavailable: the featured game couldn't load.`
  Use the existing `.card` class; add no CSS.
- In Chapter 2, when `seasons && seasons.rowCardMount` exists and the detail is null, the mount gets
  `div.card.rowcard-fallback[role=status] > p` with text `"One game, one row" is unavailable: the featured game couldn't load.`
- Normal case (`/model?sample=1`, nothing failing): behaviour unchanged — 7 steps in ch3, row card in ch2, chapters 1–6.
- Reduced motion: same fallback. Widths: the card takes the chapter's normal column width; no overflow.

## 6. Out of scope
`walkthrough.js`, `seasons.js`, `rowcard.js`, any CSS, env vars. Hero kicker (A2), model names/copy (A3).

## 7. Acceptance tests (`tests/e2e/audit/A1.mjs`)
For w in 400, 768, 1440:
- Game JSON → 404: `#ch3` not hidden; `#ch3 .walk-fallback` text includes "Walkthrough unavailable: the featured game
  couldn't load."; `#ch3 .step` count 0; `#ch2 .rowcard-fallback` exists; `#ch4 .ch .k` reads "Chapter 4",
  `#ch5 .ch .k` "Chapter 5", `#ch6 .ch .k` "Chapter 6".
- Featured pick → 404: same assertions.
- Normal load: `#ch3 .step` count 7; no `.walk-fallback` / `.rowcard-fallback`; `.ch .k` texts are Chapter 1…6 in order.
- Audit "Accept when" — *Page with a 404 on /api/game keeps 7 chapters and shows the fallback text*: `section.claim`
  plus `#ch1`…`#ch6` all not hidden in the 404 case, and the fallback text is present.
- `page.errors` empty, ignoring messages that contain "404" or "Failed to load resource" (the forced failure).
