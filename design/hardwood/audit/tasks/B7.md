# B7 · Glance court rows finish populating within 1.2 s

## 1. Problem
The glance court rows' populate animation (T1–T4) staggers by `--i × 90ms` with no cap, so with 8+ games the lower
rows take 1.2–1.4 s to finish after entering the viewport.

## 2. Repro
`/?sample=1&scene=live` at 1440 and 400 (8 games). Scroll to `[data-testid=chart]`; time from a row losing `.pre`
to its last transition ending.

## 3. Root cause
`public/static/css/tonight.css` lines ~40–44: transition delays `calc(var(--i) * 90ms + …)` on `.seg.paint` (.8s),
`.edge-line` (+.7s), `.seg.hat/.seg.short` (+.75s, .5s), `.mk` (+.45s), `.tag` (+.9s, .35s). `--i` is the row index
(set in `glance.js courtRow`). Row 7: 7×90 + 900 + 350 = 1.88 s total from the first row's start.
Animation spec: `handoff/animations/animation-spec.md` (T1–T4).

## 4. Files owned
- `public/static/css/tonight.css` (only the five `.js .gl …` transition rules at lines ~40–44)

## 5. Complete solution looks like
Today even row 0 takes 1.25 s (hatch .75s delay + .5s; tags .9s + .35s), and every row adds `--i × 90ms`.
New timings (only these numbers change; selectors, easing curves and the beat order stay):
| rule | delay (was) | delay (new) | duration (was → new) |
|---|---|---|---|
| `.js .gl .seg.paint` | `--i×90ms` | `min(var(--i),3)×50ms` | .8s → .8s |
| `.js .gl .mk` | `+.45s` | `+.4s` | .45s → .45s |
| `.js .gl .edge-line` | `+.7s` | `+.6s` | .2s → .2s |
| `.js .gl .seg.hat, .seg.short` | `+.75s` | `+.6s` | .5s → .45s |
| `.js .gl .tag` | `+.9s` | `+.7s` | .35s → .3s |
Write the stagger as `calc(min(var(--i), 3) * 50ms + .6s)` etc. (CSS `min()` inside `calc()` is fine in all targets).
Worst row: 150ms + max(.8, .85, .8, 1.05, 1.0) = 1.20 s. Beat order kept: paint → marker → edge line → hatch → tags.
- Reduced motion: `.pre` is never applied (glance.js checks `motionOn()`), so rows render complete — verify only.

## 6. Out of scope
glance.js, court.js, the count-up number animation (`countUp`).

## 7. Acceptance tests (`tests/e2e/audit/B7.mjs`)
At 1440 and 400, scene live:
- For each `.gl` row: read computed `transition-delay` and `transition-duration` of `.seg.paint`, `.edge-line`,
  `.seg.hat`/`.seg.short`, `.mk`, `.tag` inside it (parse the largest `delay + duration` among them) → assert ≤ 1.2 s
  for every row (the formula, independent of timing jitter).
- Real timing: scroll the courts into view, then measure with `transitionend` listeners on the last row's `.tag`
  elements from when the row's `.pre` was removed (MutationObserver on class) → ≤ 1.2 s + 100 ms tolerance.
- Audit "Accept when" — *Last row done ≤ 1.2s after entering.*
- Reduced motion at 400: no `.gl.pre` present after load; courts fully drawn.
- `page.errors` empty.
