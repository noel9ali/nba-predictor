# B2 · Bankroll tooltip stays inside the card for every night

## 1. Problem
The bankroll chart tooltip is clipped off the card's left edge on the first nights ("Tue, Oct 21" cut), overflows the
right edge near the last night, and covers the peak label.
Screenshots: `design/hardwood/audit/shots/B4-tooltip-clipped-left.png`, `design/hardwood/audit/shots/B4-tooltip-overflow-right.png`.

## 2. Repro
`/?sample=1&scene=live` at 400, 768, 1440. Scroll `[data-testid=bankroll]` into view (`scrollTo(p, '[data-testid=bankroll]')`),
focus it (`page.focus('[data-testid=bankroll]')`) and press ArrowLeft repeatedly (walks to night 1) and ArrowRight
(walks to the last night). Also mouse-hover the far left and far right of the chart.

## 3. Root cause
`public/static/js/tonight/season.js` `show(i)` lines ~145–157: `tip.style.left = clamp(p.x*sc, 90, w − 90)`, a guess
that assumes a 180px tooltip; `tip.style.top = p.y*sc`; CSS `.chart .tip{transform:translate(-50%,-110%)}`
(`public/static/css/tonight.css` line ~115) always places it above the point, so near the top it covers the
"Peak $…" label and can leave the card.

## 4. Files owned
- `public/static/js/tonight/season.js` (only `show()` / `hide()` and the tooltip)
- `public/static/css/tonight.css` (only `.chart .tip` rules)

## 5. Complete solution looks like
- After setting the tooltip content, measure it (`tip.offsetWidth`, `tip.offsetHeight`) and position it in host px:
  - x: `left = clamp(px, PAD + tw/2, host.clientWidth − PAD − tw/2)` with PAD = 8 (keeps the translate(-50%) model);
    if the tooltip is wider than the host minus 2×PAD (very narrow phones), use `left = host.clientWidth/2`.
  - y: above the point by default (`top = py − 12 − th`, set `transform: translateX(-50%)` via a class
    `.tip.above`); if that would go above the card's top padding (top < −(distance from host top to the card's inner
    top)) or within 14px vertically of the peak label, place it below the point (`top = py + 14`, class `.tip.below`).
    Simplest robust rule: if `py − 12 − th < 0`, place below.
  - Use `tip.style.setProperty('left', …px)` / `('top', …px)` (CSSOM, CSP-safe). Remove the old fixed 90px clamp.
- CSS: replace `transform:translate(-50%,-110%)` with `transform:translateX(-50%)` (vertical offset now in JS); keep
  colours, font, padding, `white-space:nowrap`, `z-index:5`, `pointer-events:none`. The tooltip must render above
  the SVG labels (it is an HTML sibling after the SVG with z-index — keep it so).
- The tooltip is fully inside the `.card.bcard` that contains the chart for EVERY night 1…N at 400/768/1440, for keyboard
  and mouse. The crosshair line is unchanged.
- Reduced motion: unchanged (no animation).

## 6. Out of scope
Y-axis domain/ticks (C3), label collisions (C4), step titles (C5), tooltip text format (D4 changes "bets 2-1").

## 7. Acceptance tests (`tests/e2e/audit/B2.mjs`)

ArrowRight through every night to the last. After each key: `tip = host.querySelector('.tip')`, `card =
host.closest('.card')`; assert `!tip.hidden` and the tip rect is inside the card rect (left ≥ card.left, right ≤
card.right, top ≥ card.top, bottom ≤ card.bottom, tolerance 0.5px).
- Audit "Accept when" — *Tooltip rect fully inside the card for every night (← → sweep).*
- Also hover (page.mouse.move) at x = host.left + 2 and host.right − 2, mid-height: same containment.
- `page.errors` empty.
