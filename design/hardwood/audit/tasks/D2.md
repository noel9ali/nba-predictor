# D2 · Lede kicker wraps only between parts, never with a leading "·"

## 1. Problem
On phones the Tonight kicker ("TUESDAY, NOVEMBER 17 · 8 GAMES · 0 FINAL · 3 LIVE · 5 TO COME") wraps with a line
starting "· 3 LIVE". Screenshot: `design/hardwood/audit/shots/D1-D2-phone-nav-kicker.png`.

## 2. Repro
`/?sample=1&scene=live`, `scene=final`, `scene=nobets`, `scene=offseason`, past `/?sample=1&date=2026-11-16` at 320,
360, 400, 768, 1440. Look at `[data-lede-kick]`.

## 3. Root cause
- `public/index.html` line ~85: `<p class="kick" data-lede-kick><span data-testid="date-eyebrow"></span><span data-kick-sep hidden> · </span><span data-testid="counts"></span></p>`.
- `public/static/js/tonight/glance.js` `renderLede()` ~85–96: `eyebrow = date + ' · ' + 'N games'`, `counts = 'a final · b live · c to come'`
  as plain text; the browser breaks at any space, so a line can start with "·".

## 4. Files owned
- `public/static/js/tonight/glance.js` (only the kicker lines in `renderLede`)
- `public/static/css/tonight.css` (only `.lede .kick` rules, ~221–222, plus one new rule for the parts)

## 5. Complete solution looks like
- Keep the three spans and their `data-testid`s (tests read `date-eyebrow` and `counts` text — their `textContent`
  must stay exactly as today, e.g. "Tuesday, November 17 · 8 games" and "0 final · 3 live · 5 to come").
- Inside each span, render each part as `<span class="kp">part</span>` with the separators as text between them, so
  the separator stays attached to the END of the previous part and the break opportunity is after it:
  `<span class="kp">Tuesday, November 17 ·</span> <span class="kp">8 games</span>` — i.e. part + NBSP + '·' inside
  the `.kp`, then a normal space. The outer `[data-kick-sep]` " · " likewise: make its content `·` glued to the
  previous part (use ` ·` and a trailing normal space).
  Build with createElement/textContent (or `esc()` if you use innerHTML). textContent of each testid span unchanged
  except NBSP vs space — use a regular space where the test compares text? → The validate.mjs tests don't read these
  spans; keep NBSPs, but your own test must normalise ` ` to ' '.
- CSS: `.lede .kick .kp{white-space:nowrap}`. Lines may break only between parts. No line starts with "·".
- `.lede .kick{min-height}` rules (layout-shift reservation) stay; adjust the phone min-height only if the kicker now
  needs 2 lines where it used 1 (check 400px).
- All scenes: offseason/no games ("Monday, July 20 · offseason") follow the same rule.

## 6. Out of scope
The h1 sentence (A5/D3), the board, the header (D1).

## 7. Acceptance tests (`tests/e2e/audit/D2.mjs`)
For each scene × width: get the kicker's line boxes: for every text node in `[data-lede-kick]`, use a Range per
character to find line starts (group client rects by top). Assert no line's first visible character is '·'.
Also assert `[data-testid=date-eyebrow]`/`[data-testid=counts]` normalised text matches the old format
(`/^\w+day, \w+ \d+ · \d+ games?$/` etc.). `page.errors` empty. No horizontal overflow.
