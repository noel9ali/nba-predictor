## 3. Root cause
`public/static/js/tonight/season.js` `renderBankroll()` lines ~97–125 places labels at fixed offsets:
peak label `(peak.x, peak.y − 12)`; end label `.endg` `(last.x − 8, last.y + 20)` anchor end; drawdown amount `.ddt`
beside the bracket; tonight label `.tnt` `(tx − 12, yN − 12)` anchor end; range labels `.tns` `(tx − 8, yHi/yLo + 4)`.
Designer ruling 9 (README) is implemented only as a vertical-distance check between `.tnt` and `.tns`. No check against
the series line, the drawdown line, the $1,000 base line or the range bar. CSS (`public/static/css/tonight.css`
~113–136): `.chart .lbl/.ddt/.tnt/.tns` have no halo. Step 3 hides `.endg` with `opacity:0` (line ~126) — but it is
still in the DOM and still blocks space; check the screenshot: the end label is visible beside the tonight label.
C3 (done before you) made the y-domain depend on the step and re-renders on step change.

## 5. Complete solution looks like
- **Halo**: `.chart .lbl, .chart .ddt, .chart .tnt, .chart .tns { paint-order: stroke; stroke: var(--panel);
  stroke-width: 4px; stroke-linejoin: round; }` (the card background colour — check which token the `.bcard` uses and
  match it).
- **Placement pass**: after the SVG is inserted (and after every re-render), run `placeLabels(svg, step)` that, for each
  label visible at the current step, tries candidate positions in order and keeps the first that is clear:
  - candidates: the current default, then above the anchor point (y − 14), below (y + 18), left (anchor end, x − 10),
    right (anchor start, x + 10);
  - "clear" = the label's `getBBox()` grown by 2px intersects none of: other already-placed visible labels; the
    `$1,000` base line (`.base`, a horizontal line → its y ± 1); the tonight range bar (`.tnr`, x ± 3 over its y span);
    any segment of the visible polylines (`.ln` points from `geo.pts`, `.ddl`, `.tnl`); the plot's edges (stays inside
    `pad.l … W − pad.r` and `pad.t − 14 … H − pad.b`).
  - Segment–rectangle test: a segment intersects a rect if either endpoint is inside it or it crosses any of the 4 rect
    edges (standard line-segment intersection). Use the path coordinates you already have (`pts`), not DOM parsing.
  - If no candidate is clear, apply designer ruling 9 semantics: hide the lower-priority label
    (`visibility="hidden"`). Priority: `.tnt` (Tonight) > `.ddt` > peak `.lbl` > end `.lbl` > `.tns` range labels.
    The range bar itself always stays.
- **Visibility per step**: the end label (`.endg`) is `display:none` at step 3 (not just opacity 0), so it can't sit
  beside the tonight label. Step 2: the end label avoids the red `.ddl` line via the placement pass.
- Labels that are hidden by step (opacity 0 overlays at other steps) don't take part in the pass for the current step;
  re-run the pass in `setStep` (cheap; no re-render needed when the domain didn't change).
- Phones (400): "Tonight $X" never crosses the line or the peak marker; it may move left/above/below per candidates.
- No text under 11px (`.tns` is 11px — keep).
- Reduced motion: same final positions.
