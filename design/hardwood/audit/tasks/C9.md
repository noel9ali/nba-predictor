# C9 · Model board: the ROI sits on its own line under the profit

## 1. Problem
Model Chapter 1's board cell "Profit · ROI" squeezes "+$111.67 +2.6%" onto one line inside the cell (ROI `small`
inline after the big number), so the cell looks cramped and can clip at 768–1440.

## 2. Repro
`/model?sample=1` at 400, 768, 1440: `scrollTo(p, '#ch1 .board', 1200)`; also switch seasons with the season switcher
in Chapter 1 (each season re-renders the board).

## 3. Root cause
- `public/static/js/model/alltime.js` ~166: the cell `{ label: 'Profit · ROI', value: money, small: '+2.6%' }`;
  `board.js renderBoard` appends `<small>` inside the `dd`.
- `public/static/css/components.css` ~49: `.board dd small{…margin-left:6px}` (inline); only at ≤520px (~61) it becomes
  `display:block`. `.board dd` is `white-space:nowrap`.

## 4. Files owned
- `public/static/css/components.css` (only the `.board dd small` rules)

## 5. Complete solution looks like
- `.board dd small` is `display:block; margin:6px 0 0` at every width (remove the inline margin-left and the now
  redundant ≤520px override). Font unchanged (500 12px mono, `--ink-2`).
- The cell's big number stays on one line; the ROI sits under it, left-aligned with it. All boards keep equal cell
  heights per row (grid stretch) — Tonight's boards don't use `small`, so they're unaffected (verify).
- No other board CSS changes (A6 changed the column rules; keep them).

## 6. Out of scope
The board data (alltime.js), other cells.

## 7. Acceptance tests (`tests/e2e/audit/C9.mjs`)
For w in 400, 768, 1440:
- In `#ch1 .board`, the dd containing a `small`: `small` rect top ≥ the dd's first text line bottom (use a Range on the
  dd's first text node) — i.e. on its own line; `dd.scrollWidth <= dd.clientWidth + 1` (no clipping).
- The small's text matches /^[+−±]\d+\.\d%$/.
- Tonight `/?sample=1&scene=live` at 1440: `[data-testid=tape]` and `[data-testid=season-board]` cell heights unchanged
  vs before (record before values in the test from a run before your change, or assert no `small` exists there).
- `page.errors` empty.
