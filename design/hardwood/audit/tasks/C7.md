# C7 · Season strip: split flag above the strip, season labels below; short labels on phones

## 1. Problem
Model Chapter 2's season strip: the "Feb 25, 2025 · training stops here" flag overlaps the "2024-25"/"2025-26" labels;
on phones the labels and counts truncate ("201…", "854 + …").
Screenshots: `design/hardwood/audit/shots/C5-season-strip-flag-1440.png`, `design/hardwood/audit/shots/C5-season-strip-400.png`.

## 2. Repro
`/model?sample=1` at 320, 400, 768, 1440: scroll so `#ch2 [data-scrolly2]` is pinned and in the "split" state
(scroll the scrolly ~60% through: `el.getBoundingClientRect()` → `scrollBy` until `.pin2[data-state="split"]`), or
use reduced motion (renders the final split state directly).

## 3. Root cause
- `public/static/js/model/seasons.js` `buildScrolly()` ~159–196 appends: `head, flag, labels, strip, counts, legend, table`.
  The flag (`.splitflag`, 30px tall, label positioned at the split %) sits directly above the season labels row, so its
  pill overlaps the labels of the seasons around the split. `buildStrip()` ~70–95 renders one label span per season
  (`seasonLabel` → "2024–25") and one count span (`"854 + 371"` for the split season).
- `public/static/css/model.css` ~171–207: `.slabels span`/`.scounts span` are `flex:var(--g)` with `nowrap` +
  `text-overflow:ellipsis` → truncation on narrow widths; the phone rules shrink fonts to 11px/10px.

## 4. Files owned
- `public/static/js/model/seasons.js` (only `buildStrip` and the append order in `buildScrolly`)
- `public/static/css/model.css` (only `.splitflag`, `.slabels`, `.scounts`, `.seasons` rules and their media queries)

## 5. Complete solution looks like
- New vertical order inside the card: `head, flag, strip, labels, counts, legend, table` — the flag pill sits above the
  strip (its arrow pointing down at the split line), the season labels and counts sit below the strip. Nothing else
  between flag and strip.
- Labels: each label span holds two children: `<b class="l-full">2024–25</b><b class="l-short">24–25</b>` (short =
  last two digits of the start year, en dash, last two of the end year). CSS shows `.l-full` by default, `.l-short` at
  `max-width: 560px` (the same breakpoint the file already uses for the strip; check). Never ellipsize.
- Counts: the split season's count renders as two lines on phones: `<span class="c-a">854</span> <span class="c-b">+ 371</span>`
  — inline with a space at desktop ("854 + 371"), stacked (`display:block`) at ≤560px. Other seasons show one number.
- Fonts: labels ≥ 11px, counts ≥ 11px at every width (raise the phone count size from 10px to 11px).
- If a label still doesn't fit its column at 320px (the 2019–20 column is narrow: 759 games), allow the text to
  overflow its flex cell visibly centred instead of clipping — but it must not overlap a neighbour's text: use the short
  label, and if `scrollWidth > clientWidth` after render, hide that season's count and label text and rely on the
  screen-reader table (`.sr` table already exists). Report which seasons hit this at 320.
- The flag pill never overlaps any label/count text; it may extend over the strip's top edge only with its arrow.
- Animations (`szin`, flag fade) and reduced motion unchanged.

## 6. Out of scope
Head copy, the five-number strip (`.nums`), notes, row card.

## 7. Acceptance tests (`tests/e2e/audit/C7.mjs`)
For w in 320, 400, 768, 1440 (reduced motion — final state — and normal motion scrolled into the split state):
- The flag pill rect (`.splitflag i`) intersects no `.slabels` / `.scounts` text rect.
- `.splitflag` bottom ≤ `.seasons` top + 1; `.slabels` top ≥ `.seasons` bottom − 1.
- No visible label/count element has `scrollWidth > clientWidth + 1` (no truncation) unless it was deliberately hidden.
- At ≤560px every visible label text matches /^\d{2}–\d{2}$/; at 1440 /^\d{4}–\d{2}$/.
- Rendered font sizes of visible labels/counts ≥ 11px.
- No horizontal page overflow. `page.errors` empty.
