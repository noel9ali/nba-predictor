# C3 · Bankroll chart: y-domain per step, readable tick spacing

## 1. Problem
The bankroll chart's y range is inflated to ~$1,350 on every step because tonight's "all cash" range is always included,
so the season line is squashed; y labels every $50 are crowded (worse at 768/400).
Screenshots: `design/hardwood/audit/shots/C3-bankroll-step1-1440.png` (also step2/step3 shots).

## 2. Repro
`/?sample=1&scene=live` at 400, 768, 1440. Scroll to `[data-bscrolly]`. The chart is pinned; steps change as
`.bstep[data-bs=1|2|3]` reach mid-screen (`host.dataset.step`). Drive steps by scrolling each `.bstep` to the
viewport centre (`scrollTo(p, '.bstep[data-bs="2"]', 900)`).

## 3. Root cause
`public/static/js/tonight/season.js` `renderBankroll()` line ~84:
`lo = floor(min(start, tnLo, ...ys)/50)*50 − 25`, `hi = ceil(max(tnHi, ...ys)/50)*50 + 25` — tonight's range for all
steps; ticks every $50 (line ~91) regardless of pixel spacing. `setStep(n)` (line ~197) only flips `data-step`.

## 4. Files owned
- `public/static/js/tonight/season.js` (only `renderBankroll`, `setStep`, and helpers they need)

## 5. Complete solution looks like
- `renderBankroll(step)` computes the domain for a step:
  - steps 1–2: values = series bankrolls + `start` (the $1,000 base line stays in view);
  - step 3: the same plus tonight's `tnLo`, `tnHi`, `tnNow` (live/upcoming tonight) — or the past night's point.
  - `pad = max(10, 0.06 × (max − min))`; `lo = min − pad`, `hi = max + pad`.
  - Tick step: the smallest of [10, 20, 25, 50, 100, 200, 250, 500] with `step × plotH / (hi − lo) ≥ 28` px; then
    snap `lo = floor(lo/step)·step`, `hi = ceil(hi/step)·step`. Tick labels `$1,050` style (no cents) as today.
- `setStep(n)`: if the domain group changes (1–2 ↔ 3), re-render the chart for the new step (keep `host.dataset.step`,
  keep the tooltip behaviour, keep `drewOnce`/the `pre` draw-in happening only once). Re-rendering must not replay the
  line draw-in. The step-3 `pop` class still triggers the tonight dashed-line animation.
- Everything else derived from the y scale (peak/end labels, drawdown overlay, tonight overlay, tooltip position via
  `geo.pts`) uses the current step's scale — `geo` updates on re-render.
- At steps 1–2 the line fills most of the plot height (no headroom for tonight's range). At step 3 the range bar fits.
- ResizeObserver re-render passes the current step.
- Reduced motion: steps are not scroll-driven if IO is missing… keep current behaviour; with reduced motion the chart
  still shows the right domain for the active step.

## 6. Out of scope
Label collisions (C4), tooltip clamp (already fixed in B2 — don't regress it), titles (C5), x ticks.

## 7. Acceptance tests (`tests/e2e/audit/C3.mjs`)

  assert the step-1 top tick < the step-3 top tick when tnHi > series max.
