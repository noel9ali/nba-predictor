# B4 · Drawer tale-of-the-tape bars: fixed scale per stat; 0 vs 0 shows empty bars

## 1. Problem
In the ticket drawer, each tale-of-the-tape row scales both bars to the pair's max, so 110 vs 104 points look nearly
identical (both ~full), and 0 vs 0 rest days render as two full bars.
Screenshot: `design/hardwood/audit/shots/B5-drawer-tape-bars.png`.

## 2. Repro
`/?sample=1&scene=live` at 400, 768, 1440: click the first `.ticket__hit`, wait for `.drawer [data-tape] .tt` rows
(detail JSON loads from `/sample/game-<id>.json`). Look at every `.tt` row's `.b.l i` / `.b.r i` widths.

## 3. Root cause
`public/static/js/tonight/drawer.js` `tapeRows()` lines ~172–198: `max = Math.max(a, h) || 1` and
`width = v / max * 100%` → the larger side is always 100%, and equal small values (1 vs 1 rest day) become two full
bars. (Check what 0 vs 0 renders today and describe it in your report.) `TAPE` (line ~10) lists the stats.
Sample value ranges across all games: elo 1420–1633, rest 0–3, pts 105.7–120.6, fg .437–.499, reb 40.3–47.8,
ast 23.3–30.4, tov 10.9–16.6, stocks 10.4–17.8.

## 4. Files owned
- `public/static/js/tonight/drawer.js` (only `TAPE` and `tapeRows`)

## 5. Complete solution looks like
- Each stat has a fixed domain `[lo, hi]` (league-plausible range for a last-10 average); bar width =
  `clamp((v − lo) / (hi − lo), 0, 1) × 100%`. Add the domain to `TAPE` rows:
  Elo [1300, 1750]; Rest days [0, 4] (values ≥ 4 fill the bar); Points [100, 125]; FG% [0.42, 0.52];
  Rebounds [38, 52]; Assists [20, 32]; Turnovers [10, 18]; Stl+blk [10, 20].
- Turnovers: lower is better; the bar still shows the raw amount (more turnovers → longer bar). The "better" mark
  logic (`betterSide`) is unchanged: the better side's bar gets `.better` and its value is bold.
- 0 vs 0 (e.g. rest days) → both bars width `0%`. Equal values → equal widths. 110 vs 104 points → 40% vs 16%.
- Widths are set via `i.style.setProperty('width', …)` as now. No CSS changes.
- Same in every scene; reduced motion unchanged.
